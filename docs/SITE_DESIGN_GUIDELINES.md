# Design guidelines for bilingual data sites

- **Sticky top row.** Keep one slim row visible while scrolling in either direction. Put the clickable site title and icon on the left and the ES / EN toggle on the right.
- **Language switch.** Use a compact text toggle with a clear active state and accessible language names. Default to the reader's device language if ES/EN. Otherwise, EN as default. Preserve the current selections and view when switching languages. Give each language a shareable URL and localize the interface and sharing metadata.
- **Buttons and selections.** Remove the external coloured rectangles or squares around clicked or selected controls. Show the active option within the control itself, using a fill, underline or stronger text as appropriate. Keep keyboard focus visible and distinct from selection. A prominent search field can be pill-shaped.
- **Footer.** Keep it thin and at the end of the page. On desktop, put the bold, underlined author-site link on the left, localized author and data credit in the centre, and the project title and icon on the right. On mobile, keep the author link on the left, right-align the credit and drop the repeated brand. Put methodology and sources near the data credit. Use the existing source text as the link when it can open those details.
- **Mobile first.** Start with a narrow, vertical layout, readable type and comfortable tap targets. Give desktop a layout suited to its extra space. Reuse existing rows for actions such as Share and keep labels and comparable values aligned. Test long names and both languages. When the phone keyboard opens, keep the search field and a usable list of suggestions visible above it.
- **Brand.** Give each project its own title and small, recognizable icon within the same visual family. Put the icon to the right of the title, omit decorative trailing punctuation and reuse the icon as the favicon.
